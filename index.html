01 / SYSTEMS
Active · engine in progress

Matching Engine (Threadweaver)

Moving data between threads is limited by cache coherence, not arithmetic. I am building a low-latency matching engine from the bottom up, and its first layer, Threadweaver, is a family of lock-free ring buffers in C++23, with every head on its own 64-byte cache line, power-of-two mask indexing, and 2 MB huge-page shared memory.

The buffers and allocators are done and benchmarked at 1.25B ops/sec with one producer and consumer on one core's L1, and 400M ops/sec with eight producers, without a single mutex. The order book and matching logic on top are next.

02 / ML INFRA
Active

FlexGEMM: CPU fallback

Running TRELLIS 2 ran me out of VRAM, and FlexGEMM's sparse 3D convolution backend only had GPU kernels for building output coordinates. I'm writing CPU versions so it works on machines with little or no GPU memory.

Both output-coordinate kernels now have native C++17/OpenMP CPU versions. They return exactly the same coordinates as PyTorch's reference path and run 40–400× faster on my 8-thread laptop CPU. The submanifold neighbour map still runs through a PyTorch fallback; a native kernel is next.

03 / AI RESEARCH
Private · Active

Recursive-MAS MiniCPM

A recursive-thinking multi-agent system aimed at cutting the tokens a model spends thinking, so inference gets faster on edge devices. First step: a Qwen3.5-based transformer in plain PyTorch, with no Hugging Face Transformers, so every tensor is visible.

Three of every four layers use linear attention (gated delta rule, roughly O(N)), and grouped-query attention shrinks the KV cache 4×. Next up: DCT analysis for weight compression.

Threadweaver Core

Ultra-Low Latency Concurrency Infrastructure in C++23

🕒 12 min read View on GitHub
C++23 Lock-free Atomics Huge Pages Callgrind LTTng

Overview

Threadweaver Core is a from-scratch concurrency infrastructure library engineered for ultra-high-throughput, ultra-low-latency scenarios. The project explores the fundamental limits of inter-thread communication on modern hardware, achieving peak SCSP (Simple Cell-Simple Path) throughput of 1.25 billion operations per second through careful hardware-aware design.

The library provides a hierarchy of concurrency primitives — from simple single-producer/single-consumer ring buffers to scalable multi-producer cell-lockable designs — each optimized for specific contention patterns. The key insight driving the design is that contention should be distributed across cells rather than bottlenecked at a single commit point.

Architecture

Ring Buffer Designs

The core data structure is a ring buffer, but not the textbook variety. Three distinct implementations target different contention profiles:

  • Simple Branchless Buffer — Uses inline x86 cmov instructions to replace conditional branches with conditional moves, eliminating branch misprediction penalties. Ideal for single-producer/single-consumer paths.
  • Three-Pointer Lock-Free MPSC — Separates write_head (CAS-wait claim), commit_head (prevents false sharing), and read_head. The separation ensures producers never contend with each other at the cache-line level.
  • Cell-Lockable Design — Distributes contention across individual cells using sub-byte atomicity via lock bts. Multiple concurrent writers can operate on different cells simultaneously, achieving 400M ops/sec in SCMP (Shared Memory Concurrent Path) mode.

Memory Layout

Every data structure is designed around cache-line awareness. The CacheLineSlot<D, Header> template guarantees exact 64-byte alignment via static_assert, ensuring no false sharing between adjacent slots. The CacheLinePacked<D, Header> union provides dual access — raw uint64_t[] for zero-copy serialization and structured CacheLineSlot for type-safe operation.

For the cell-lockable variant, CacheLineUint8LengthHeaderPacked<D> packs both a lock bit and length into a single uint8_t, enabling sub-byte atomic operations via lock bts bit-manipulation.

Key Optimizations

Huge Pages & TLB Elimination

Standard 4KB pages create TLB pressure at scale. By using 2MB Huge Pages via mmap(MAP_SHARED | MAP_ANON | MAP_HUGE_2MB), we eliminate TLB misses entirely for buffers up to 512MB, enabling linear scaling where smaller pages would plateau.

Zero-Copy IPC

The custom ARC-based shared memory allocator enables zero-copy inter-process communication. Combined with POSIX shm_open/shm_unlink lifecycle management and MREMAP_MAYMOVE runtime resizing, data passes between processes without a single memcpy.

Compile-Time Safety Contracts

C++20 concepts enforce safety contracts at compile time:

  • PowerOfTwo<N> — Enforces power-of-two capacity for bitwise modulo indexing
  • LockableCell<T> — Contract requiring try_lock/unlock/clear_data/contains_data
  • ReadLockableIndex<Layout> / WriteLockableIndex<Layout> — Validates guard types at compile time
  • LayoutVerification<T> — Checks MemLayout/data_type/index_type/atomic heads/operator[]
RAII Guard Hierarchy

A four-layer RAII guard system ensures locks are always released:

  1. SingleResourceLockGuard — Stateless, single-resource lock
  2. InstSingleResourceLockGuard — Instance-storing variant
  3. InstSingleResourceLockGuardWrapper — Composable chaining
  4. TemplateLockedLockGuard — Type-state locking: T<false> → T<true>

Profiling was done with callgrind (instruction counting per function/benchmark) and kcachegrind for flow graph visualization. Non-blocking execution tracing used LTTng-UST with URCU (Userspace RCU) for safe memory reclamation.

Lessons Learned

  • False sharing is the silent killer. Separating the commit_head from write_head in the MPSC design was the single biggest throughput improvement — a single cache-line bounce was costing 30% of peak performance.
  • Branchless isn't always faster. cmov wins when branches are unpredictable, but predictable branches with good branch prediction can outperform forced branchless code. Profile, don't guess.
  • Huge pages matter more than you think. The difference between 4KB and 2MB pages at 512MB buffer sizes isn't incremental — it's the difference between linear scaling and a hard plateau.
  • Compile-time contracts catch real bugs. The C++20 concept system caught three categories of layout mismatches during development that would have been subtle runtime corruption otherwise.
  • Cell-lockable scales better than 3-pointer. The commit_head bottleneck in the 3-pointer approach creates contention under heavy multi-producer load. Cell-lockable distributes locks across cells proportionally to buffer capacity, yielding 3× improvement at 8×8 threads.
